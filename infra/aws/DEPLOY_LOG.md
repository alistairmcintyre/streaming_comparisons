# AWS/EKS deployment — error log

Every failure hit taking the streaming comparison from local compose to EKS, with
its root cause and fix. One line each, in the order encountered. Companion to
`HEALTHCHECK.txt` (how to check) and `README.md` (how to run).

Pattern worth knowing: almost every entry below was found only by fixing the one
before it, so a "fixed" pipeline usually just means the next layer became reachable.

| 84 | Enabling Kubernetes HA crash-looped the Fluss JobManager immediately | `UnsupportedFileSystemSchemeException: Could not find a file system implementation for scheme 's3'` at `KubernetesHaServicesFactory.createHAServices`. `paimon-s3` in the image is Paimon's FileIO — it does NOT register a Flink FileSystem, so anything **Flink itself** opens on s3:// (HA blob store, savepoints) fails. flink-paimon's Dockerfile already installs `plugins/s3-fs-hadoop`; the fluss image never did, because nothing had opened s3:// through Flink there before → add the plugin. No JM meant no jobs, which is why "fluss lake has NO data files" reappeared |
| 85 | Paimon gold job would not submit: `First row streaming reading is not supported` | `merge-engine = first-row` with `changelog-producer = 'none'` passes SchemaValidation but is invalid at RUNTIME for a streaming read — only `lookup` or `full-compaction` work. The gold job streams from silver.trades, so 'none' silently cost the gold job while bronze and both silvers ran fine. Schema-valid and runtime-invalid is its own category: passing CREATE TABLE proves nothing about whether you can read it |
| 86 | The unset-variable guard blocked a valid deploy on its first use | it scanned `${FLINK_CHECKPOINT_BASE}` out of a **YAML comment** in 92-flink-paimon.yaml — a comment written to explain DEPLOY_LOG #27, about that same variable. The real config uses `${PAIMON_BUCKET}`, which is exported → strip comment lines before scanning |
| 87 | Spark latency emit failed on all three engines for a whole day: `No module named 'kafka'` | the ECR images PREDATE the commit that added kafka-python — `spark-iceberg` pushed 06:28:18, the Dockerfile committed 06:28:47. The build raced the commit and lost by 29 seconds; every run since passed `skip_build=true` and inherited them. Nothing failed loudly, the emit just never worked → tag every image with a CONTENT HASH of its build inputs and refuse `skip_build` when ECR has no image matching the current sources. Timestamps were the first idea and are a heuristic (clock skew, no-op rebuilds, rebases); a content hash is an equality test, which is what Docker layer caching already does one level down |

## Recurring gotchas (cost us time more than once)

- A fresh cluster only trusts its creator: re-add your SSO access entry or the console/kubectl says **Unauthorized**.
- `terraform destroy` piped through `grep` looks hung — it is block-buffered; check `aws eks describe-cluster`, not the pipe.
- `pgrep -f <pattern>` inside a script whose own command line contains that pattern kills the script's own shell; use `pgrep -x`.
- Destroying with `-refresh=false` leaves stale entries in state; reconcile with one refresh-enabled destroy before the next run.
- `busybox nslookup` does NOT apply search domains the way glibc/Java do: it returned NXDOMAIN for `svc.kafka.svc` and sent me chasing a DNS problem that did not exist (`getent` inside the real image resolved it fine). Test DNS with the resolver the app actually uses.
- Karpenter reporting `karpenter.sh/initialized In [true]` / `registered In [true]` inside a "no instance type has enough resources" error means it is only considering EXISTING nodes — the real failure is in `failed launching nodeclaim`, not the scheduling message. Always read both.
- **A granted Service Quotas request shows as `CASE_CLOSED`, and the new value takes ~30 minutes to appear in `get-service-quota`.** Closed does not mean refused — I called an approved increase a refusal by checking the API immediately. Read the case correspondence, or wait out the propagation delay.
- **Hand-attached IAM policies block `terraform destroy`.** Anything added with `put-role-policy` to unblock a live run must be mirrored into Terraform, or the role cannot be deleted at teardown.
- **Money is never a float.** price is NUMERIC(12,4) at the source; every engine now carries DECIMAL(12,4) and DECIMAL(38,4) for the running sum. Floating point would not fail — it would drift silently in the gold aggregate, which is precisely what the benchmark measures.
- **Lenient parsers turn type errors into silent NULLs.** `json.ignore-parse-errors: true` (Flink) and permissive `from_json` (Spark) both mean a schema mismatch produces NULL rather than an error. Cast explicitly at the boundary.
- **"RUNNING" is not "working".** Both engines sat RUNNING, consuming Kafka and advancing checkpoints, while writing empty commits for hours. Offsets advancing only proves the SOURCE is read, not that rows survive the transform. Check add-actions/data files, not pod status.
- **Compare AWS config against docker-compose when behaviour differs.** Two silent data-loss bugs (#50, #51) were settings compose had and the k8s manifests did not.
- **Table properties are part of the create contract.** Both Delta (`createIfNotExists`) and Paimon (schema file in S3) refuse or silently ignore a changed property set on an existing table. Any property you might want to change later must be converged explicitly (ALTER TABLE), not just declared at create time.
- **Verify with the credential path production uses.** Testing the DynamoDB LogStore locally with static env credentials passed, then failed on EKS twice — first missing `aws-java-sdk-sts` (IRSA needs STS), then missing DynamoDB IAM permissions. Neither is reachable with static creds. Run the check in-cluster under the real ServiceAccount.
- **Telemetry must not load the thing it measures.** Two separate instances: a `foreachBatch` latency emit that took a second Spark action on an uncached DataFrame, and Flink latency INSERTs submitted as their own jobs re-reading the whole Kafka topic (#58). Both roughly doubled the work in the pipeline being timed. Attach to the pass the engine is already making (`observe()`, `STATEMENT SET`), never add one.
- **A metric that depends on a delivery chain can go silently to zero.** The Kafka latency emit reports nothing if the emit breaks, and nothing looks like fast. The headline processing delay is therefore read out of the gold tables themselves — `commit_ts - last_updated_at`, a property of the data that was written (#56-#57 are the same lesson for correctness: an engine absent from Glue contributes no row rather than a failing one).
- **Uniform beats clever when the point is comparison.** `opened_at` reset-on-flat is easy in a Spark MERGE and impossible as a pure Flink fold; adopting it would have made the two engine families hold different values for identical input and broken the cross-engine reconciliation. Same reasoning forced OPEN/CLOSED over LONG/SHORT/FLAT (#60).
- **Shell checks that emit the wrong SHAPE misreport silently, and they have now bitten three times in one day.** `grep -c` exiting 1 on zero produced `"0\n0"` and failed a clean teardown (#79); `cut -d: -f3` over a 6-partition topic produced six lines and called an 800k-message topic empty; `awk '{s+=$5}'` summed LOG-END-OFFSET instead of LAG so a drain could never complete. Assert the shape — one number — not just the command.
- **A metric nobody collects and an alert nobody wrote are the same thing: silence that reads as health.** The Flink PodMonitor scraped a port that was never opened (#61) and consumer lag was never exported at all (#62), so two of the three most important health signals in the system did not exist — while the dashboard looked fine. Before writing an alert, prove the metric arrives.
- **Measure at a defined point, or the measurement is a race.** Every correctness figure was taken with the generator still running (#68), so gold trailing silver was indistinguishable from data loss. Drain first, and record *whether* you drained alongside the numbers.
- **Unbounded is a property of the plan, not the code.** `SUM` folds under retraction; `MIN`/`MAX` do not, and the same query is O(keys) or O(rows) depending purely on the source's DECLARED changelog mode (#67, #72). What the stream actually contains is irrelevant — Flink plans on the declaration. Both engines needed `first_row`/`first-row` to declare insert-only. Read the connector's `getChangelogMode()`; do not reason about the data.
- **Denormalising a dimension into a current-state table needs a stated temporal semantic, or it has none.** `country`/`tier` in gold were "whatever the last batch saw" (#74) — not current, not as-of-fill, just an artifact of batch boundaries. That is the kind of thing a reviewer catches immediately and it cost a 15s rescan in Spark and 2x book state in Flink to get wrong. Facts in the fact table; attributes joined at read time, LEFT.
- **"Reuse the existing artifact" needs a provable identity, not a plausible one.** `skip_build=true` trusted ECR to hold the right images and it held images 29 seconds too old (#87). Commit ordering looked fine; the image content was not checked. Anything that skips work must compare what IS against what SHOULD be by content, the way Docker keys a layer.
- **Schema-valid is not runtime-valid.** Paimon accepted `first-row` + `changelog-producer=none` at CREATE TABLE and then refused to stream-read it (#85); Fluss accepted an HA `storageDir` on s3:// and then could not open it (#84). Validation at declaration time says nothing about whether the thing can actually be USED — and both failures presented as a missing job rather than an error at the point of the mistake.
- **Defaults are not a retention policy.** Kafka topics (#64), the accounts dimension's cleanup policy (#65), Fluss datalake compaction (#66) and Paimon snapshot counts were all inherited rather than chosen. Three of the four were wrong for a long-running system; one (`table.log.ttl` = 7d) was already fine — which is only knowable by reading the defaults, not by assuming either way.
- Two bugs of the same shape (#22, #39): a manifest sets one env-var name while the code reads another, and a *compose-era default* in the code hides the mismatch instead of failing loudly.
